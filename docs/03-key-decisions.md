# Ключевые решения

## Решения

1. **Без бэкенда.** Сайт — чистый клиент: не нужен деплой-сервер, данные
   не покидают машину. Цена: HTTPS обязателен (WebUSB), беспроводного
   режима в v1 нет.
2. **One-shot shell для команд** (новая сессия на команду: OPEN → данные → CLSD).
   Нет интерливинга, нет framing-протокола ответов, просто и надёжно.
   Overhead по USB пренебрежим. Постоянные сессии — только
   для стримов (logcat, долгие команды).
3. **Exit code через маркер**: `cmd; echo __QWM_<rand>__:$?` — случайный
   6-символьный суффикс на запрос, чтобы не коллизировать с выводом команды.
4. **Файлы через SYNC-сервис, а не shell** (`cat`, base64): binary-safe,
   без экранирования shell, нативный прогресс и причины FAIL.
5. **Мультиплексор в ADB Core**: local/remote ID выдаёт core (счётчик с 1);
   сервисы открывают стримы по имени.
6. **Ограниченная очередь записи** (≤ 8 чанков in-flight на push).
   USB-level flow control защищает устройство, очередь — память браузера.
7. **Глобальный EventBus**: все слои пишут лог (usb/adb/services) → store
   → вкладка «Log».
8. **Единый источник протокольных констант** — `adb/constants.ts`,
   верифицируется в M0.5 (см. 05, раздел «Верификация»).
9. **Последовательные очереди для долгих операций** (файлы, бэкап, установка):
   не создавать конкуренцию за ресурсы шлема.
10. **Честный «недоступно»**: настройка/операция питания, не работающая
    на конкретной модели, не скрывается — UI показывает причину.

## Модель ошибок

| Слой | Ошибка | Обработка |
|------|--------|-----------|
| USB | устройство отключено | сессия → CLOSED, store → RECONNECT_WAIT |
| USB | пользователь отказал в устройстве | показать причину |
| ADB | mismatch checksum/magic | закрыть сессию, фатальная ошибка |
| ADB | устройство не отвечает (watchdog 15 c) | закрыть сессию, RECONNECT_WAIT |
| sync | FAIL + причина (EACC/ENOS/…) | показать причину пользователю |
| shell | exit code ≠ 0 | вывод + код пользователю |

## Конкурентность

- Одна запись: все write идут через одну FIFO-очередь в ADB Core.
- Один цикл чтения в ADB Core: dispatch пакетов по (command, id) в стримы.
- Сервисы не синхронизируются между собой — порядок гарантирует core.
- Долгие операции — очереди на уровне features.

## Безопасность

- Сайт = полный shell на устройстве. Нет сторонних скриптов,
  CSP `default-src 'self'`, нет аналитики, в v1 — ноль сетевых запросов.
- HTTPS (secure context) обязателен в продакшене.
- Первый-визит модалка: «у сайта полный доступ к устройству».
- Никаких секретов на клиенте.
