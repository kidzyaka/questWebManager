## Открытые вопросы (проверять на шлеме)

1. Точный формат вывода `ls -l` (дата).
2. Работают ли `shutdown -p` / `poweroff`.
3. Работают ли `reboot recovery` / `reboot bootloader`.
4. Способ входа в recovery на каждой модели.
5. Поддерживает ли recovery Quest ADB sideload.
6. Формат OTA-пакета Meta, примет ли его sideload.
7. `setprop service.adb.tcp.port 5555; stop adbd; start adbd`
   (путь к беспроводному v2).
8. Рабочие ключи `settings` (режим исследования).
9. toybox: `du -sk`, `find -type f`, `df -h`.
10. Отваливается ли ADB при блокировке шлема.

## Тест-матрица

Среда: Windows/macOS/Linux × Chrome/Edge (latest).
Устройства: Quest 2 (обязательно), Quest 3 или 3S (обязательно),
Quest Pro (если доступен).

По фичам (happy + edge):

- **Подключение**: первый раз (промпт), reconnect (без промпта), отключение
  в idle, отключение во время push, плохой кабель, заблокированный шлем.
- **Файлы**: 1 MB, 1.5 GB, 100 файлов, кириллица, коллизии
  (overwrite/skip/rename), read-only каталог, ENOS; download одного файла,
  каталога на 1000 файлов, пустого каталога, имени в 255 символов; удаление
  файла / каталога с содержимым / текущего каталога (guard) / `/`
  (жёсткий guard); переименование в существующее.
- **APK**: маленький, 500 MB, обновление, даунгрейд (-d), битый APK,
  нет места; список (system + third-party); удаление (third-party,
  system «скрыть» + вернуть); запуск / force-stop.
- **Настройки**: на каждую верифицированную запись: запись → видимое
  изменение на шлеме → чтение → совпадение; пресет: сохранить → поменять →
  применить → совпадение; режим исследования: diff для ≥ 2 настроек.
- **Питание**: reboot (соединение вернулось, данные целы); выключение
  (после — ручное включение).
- **Бэкап**: полный бэкап → восстановление на том же устройстве (приложения
  работают, настройки совпадают); /sdcard 2 GB (лимит), > 2 GB
  (предупреждение); восстановление с чужой модели (предупреждение);
  прерванный бэкап — мусора в /data/local/tmp нет.
- **Стабильность**: 30 мин logcat tail; 20 последовательных операций
  без утечки стримов.

## Вехи

| # | Что | Критерий готовности |
|---|-----|--------------------|
| M0 | Каркас, стек | `npm run dev`, приложение открывается, линтеры зелёные |
| M0.5 | Верификация протокола | `adb/constants.ts` сверен; юнит-тесты: CNXN + push/pull 1 KB по mock (capture) |
| M1 | USB + ADB Core + Shell + вкладка Device | подключение к реальному шлему, `shell:echo` работает, DeviceInfo заполнен, disconnect → баннер, reconnect |
| M2 | Sync + файловый менеджер + менеджер APK | push/pull 1 GB с прогрессом; полный цикл APK |
| M3 | Настройки (реестр v1, ≥ 10 верифицированных) + питание + режим исследования | 10 настроек работают на двух моделях |
| M4 | Бэкап/восстановление | полный бэкап → восстановление на том же устройстве, отчёт |
| M5 | UX-полировка: logcat, вкладка Log, тосты, первый-визит модалка, диагностика драйвера | демо-сборка по HTTPS |
| M6 | (эксперимент) ассистент прошивки | sideload тестового пакета — или честное «не поддерживается» |

## Definition of Done (v1)

- M0–M5 готовы, матрица проходит минимум на 2 устройствах.
- README для пользователя: как подключиться, как включить ADB, драйвер
  Windows.
